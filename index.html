    BLUE TEAM: CYBER DEFENSE LAB

    THE SCENARIO: It is Monday of finals week at Cambridge. Carlos, the IT director, is on a plane to a conference with his phone off. You are the student intern on the cyber team, and this morning you were handed the keys to school-srv01, the server that runs the school website, the gradebook, and the final exam files.

    At 7:42 AM an anonymous email arrives: "Finals are cancelled. We own your server by lunch. -- NightOwl"

    Over the school day NightOwl will try ten different attacks. For each one you must investigate with terminal commands, figure out what they did, and shut it down. Be precise: breaking real services, deleting real files, or locking out real staff costs points.

    EASY (Rookie): clear orders that tell you where to look, objectives listed, free hints, and a relaxed countdown with no penalty.
    HARD (Veteran): you only get the symptoms. Objectives stay hidden until you complete them, the attacks have extra tricks and decoys, hints cost points, and a tight countdown clock resets the incident if it runs out.

    Your progress saves after every incident, so you can close the tab and pick up later with Resume.

    FIELD TRAINING

    Two interactive drills for skills you'll use in the incidents. Practice here, then start the game.

    In a brute-force attack the login log fills with "Failed password" lines. The attacker is the address that appears again and again. Staff computers (addresses starting with 10.) might fail once from a typo, but not dozens of times. Count them and the attacker stands out.

    Linux permissions are three groups — owner, group, everyone else — each with read (4), write (2) and execute (1). Add the numbers in each group to get the chmod code. Toggle the boxes and watch the code change.

    Toggle boxes, or load an example. 640 means the owner can read/write, the group can read, and everyone else is locked out — the right setting for a secrets file.

    FIELD MANUAL

    ls -la [dir]List files. -l shows permissions, -a shows hidden files (names starting with a dot).
    cd / pwdChange folder / show current folder.
    cat FILEPrint a file. Also head and tail.
    grep WORD FILEShow only lines containing WORD. -v shows lines that do NOT match, -c counts.
    cmd | cmdPipe: send one command's output into another. Example: ps aux | grep nginx
    ps aux / topShow running processes, their PID, and CPU use.
    kill PIDStop a process by its PID number.
    ss -tulnShow which network ports are open (also netstat -tuln).
    systemctl status|stop|disable NAMECheck a service, stop it now, or keep it from starting at boot.
    ufw statusShow firewall rules.
    ufw deny from IPBlock an IP address at the firewall.
    chmod MODE FILEChange permissions. 640 = owner read/write, group read, everyone else nothing.
    cat /etc/passwdList user accounts. The third field is the UID. Only root should have UID 0.
    userdel NAMEDelete a user account (or passwd -l NAME to lock it).
    crontab -lList scheduled jobs. crontab -r removes ALL of them. crontab - loads a new list from a pipe.
    rm FILEDelete a file.
    cp -r SRC DSTCopy a file or folder (useful for restoring backups).
    brief / hint / nextLab commands: re-read the alert, get a hint, go to the next mission.

    Tip: you can put sudo in front of any command. Up-arrow recalls earlier commands.
